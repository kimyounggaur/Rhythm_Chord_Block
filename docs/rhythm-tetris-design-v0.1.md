# 리듬 테트리스(가칭) 설계서 v0.1

- 작성일: 2026-11-02
- 범위: 리듬 테트리스 **1인 모드**. 화음 뿌요·대전 모드는 별도 문서로 다룬다.
- 대상: 음표 길이와 박자표를 배운 적 있는 학생(기초 있음). 뿌요뿌요 테트리스식 대전 게임의 '리듬' 축이 된다.
- 문서 사용법: 개발 단계(§17)를 Claude Code에 요청할 때, 해당 단계 절과 §7·§8·§15·§18·부록을 함께 전달한다.
- 리듬 표기 약어(문서 전체 공통): `e`=8분음표, `q`=4분음표, `q.`=점4분음표, `h`=2분음표, `h.`=점2분음표, `w`=온음표, `_`=붙임줄(tie). 예: `h q. e` = 2분·점4분·8분음표.

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 핵심 규칙 | **한 줄 = 한 마디.** 줄이 빈칸 없이 채워지면 그 줄이 마디로 읽혀 연주되고 사라진다. |
| 칸 | 1칸 = 8분음표 하나. 4/4박자면 가로 8칸. |
| 음 | 같은 조각이 한 줄에서 차지한 연속 칸 = 음 하나. 길이 1·2·3·4칸 = `e` `q` `q.` `h` |
| 음높이 | 조각 종류(7종) = 계이름(도~시) |
| 보너스 | 당김음, 화음 마디, 여러 마디 동시 완성(동기·악절), 리듬 패턴 도감 |
| 타이밍 판정 | 없음. 소리·터치 지연의 영향을 받지 않는다. |
| 플랫폼 | 모바일 웹(세로 화면) 우선, 데스크톱 키보드 지원 |

## 2. 설계 원칙

1. **테트리스 규칙은 바꾸지 않는다.** 음악 요소는 "줄이 지워지는 순간"에 얹는다. 게임의 재미가 그대로 남는다.
2. **입력 타이밍 판정은 넣지 않는다.** 박에 맞춰 누르는 요소는 기기마다 소리·터치 지연이 달라 어긋난다.
3. **모든 보너스는 실제 음악 규칙에서 나온다.** 게임용으로 지어낸 규칙은 넣지 않는다.
4. **정답이 분명한 것부터 가르친다.** 음표 길이·마디 → 센박·당김음 → 박자표 → 화음 → 붙임줄·표기.
5. **원작의 외형·이름을 쓰지 않는다.** 보드 크기, 색, 이름이 모두 원작과 다르다(§19).

## 3. 음악 ↔ 게임 대응표

| 음악 | 게임 | 비고 |
|---|---|---|
| 마디 | 보드의 가로 한 줄 | 줄 완성 = 마디 완성 |
| 8분음표 1개 길이 | 칸 1개 | 모든 박자표에서 같다 |
| 박자표 | 보드 가로 폭 | 4/4=8칸, 3/4=6, 6/8=6, 9/8=9, 12/8=12 |
| 음 하나 | 한 줄 안에서 같은 조각(같은 개체)이 차지한 연속 칸 | 종류가 같아도 다른 개체면 다른 음 |
| 음표 길이 | 연속 칸 수 | 1=`e` 2=`q` 3=`q.` 4=`h` |
| 계이름 | 조각 종류 | I=도 O=레 T=미 S=파 Z=솔 J=라 L=시 |
| 센박·여린박 | 칸의 위치 | 보드에 박 구분선으로 표시 |
| 당김음 | 시작한 자리보다 센 박을 덮으며 이어지는 음 | 보너스 |
| 화음 | 한 마디의 음이 모두 한 주요3화음(Ⅰ·Ⅳ·Ⅴ)에 속함 | 보너스 |
| 붙임줄 | 같은 종류 조각의 음이 이어짐(옵션 규칙) | 온음표·점2분음표가 생긴다 |
| 동기(2마디)·작은악절(4마디) | 2줄·4줄 동시 완성 | 보너스 |
| 쉼표 | 미완성 줄의 빈칸 | 지워지지 않는다. '악보 보기'에서 쉼표로 표시(옵션) |
| 템포 | 레벨별 BPM | 낙하 속도도 BPM에 묶인다(§6.2) |

## 4. 보드·박자표·조각

### 4.1 보드
- 가로 폭 W = 박자표의 8분음표 수. 세로 = 보이는 16줄 + 숨겨진 2줄(조각이 나타나는 영역). 총 18줄.
- 좌표: x=0 왼쪽, y=0 맨 위(숨김). 보이는 영역은 y=2~17.
- 줄 안의 선: 박마다 얇은 세로 점선, 마디 첫 칸 왼쪽은 굵은 실선(세로줄), 마디 중간선(4/4의 4번째 칸 뒤)은 중간 굵기.
- 겹박자(6/8·9/8·12/8)는 3칸씩 배경을 번갈아 칠해 박 묶음을 보여 준다.
- 스테이지 3부터 보드 위쪽에 박 번호 `1 · 2 · 3 · 4 ·`를 표시하고 센박 열 배경을 조금 밝게 한다.
- 폭이 다르면 난이도가 달라진다. 6칸 보드는 같은 레벨에서 낙하 간격을 1.3배로 늘린다(§6.2).

### 4.2 박자표 상수표 (JSON은 부록 A)

세기 값: 3=센박, 2=중간센박, 1=여린박, 0=박 사이(뒷박)

| 박자표 | 폭 | 박 시작 칸 | 칸별 세기 | 기 묶음 | 표기 묶음(가상 세로줄) |
|---|---|---|---|---|---|
| 4/4 | 8 | 0,2,4,6 | [3,0,1,0,2,0,1,0] | [2,2,2,2] | [4,4] |
| 3/4 | 6 | 0,2,4 | [3,0,1,0,1,0] | [2,2,2] | [6] |
| 6/8 | 6 | 0,3 | [3,0,0,2,0,0] | [3,3] | [3,3] |
| 9/8 | 9 | 0,3,6 | [3,0,0,2,0,0,2,0,0] | [3,3,3] | [3,3,3] |
| 12/8 | 12 | 0,3,6,9 | [3,0,0,1,0,0,2,0,0,1,0,0] | [3,3,3,3] | [3,3,3,3] |
| 5/4 (확장) | 10 | 0,2,4,6,8 | [3,0,1,0,1,0,2,0,1,0] | [2,2,2,2,2] | [6,4] |
| 7/8 (확장) | 7 | 0,2,4 | [3,0,1,0,2,0,0] | [2,2,3] | [4,3] |

- 2/4는 4칸이라 보드로 쓰기 어렵다. "한 줄 = 2마디" 변형으로 나중에 검토(§19).
- 기 묶음 = 8분음표끼리 기(beam)로 잇는 단위. 표기 묶음 = 음이 그 경계를 넘으면 잘라서 붙임줄로 적는 단위(§8).

### 4.3 조각 7종

| 조각 | 계이름 | 음 | VexFlow 키 | 색 |
|---|---|---|---|---|
| I | 도 | C4 | c/4 | 빨강 #E53935 |
| O | 레 | D4 | d/4 | 주황 #FB8C00 |
| T | 미 | E4 | e/4 | 노랑 #FDD835 |
| S | 파 | F4 | f/4 | 초록 #43A047 |
| Z | 솔 | G4 | g/4 | 파랑 #1E88E5 |
| J | 라 | A4 | a/4 | 남색 #3949AB |
| L | 시 | B4 | b/4 | 보라 #8E24AA |

- 색은 무지개 순(도=빨강)이라 원작 색과 다르다. 칸 위에 계이름 글자를 함께 표시한다(색각 이상 대응 + 학습).
- 한 조각이 한 줄에 남기는 연속 칸 수: I=1 또는 4, O=2, T=1·2·3, S/Z=1·2, J/L=1·2·3. 한 조각은 한 줄에서 항상 하나의 연속 구간만 만든다. 따라서 한 마디의 음 개수는 최소 2개(붙임줄 없을 때)~최대 8개(4/4).
- 등장 순서: 7-bag. 7종을 한 묶음으로 섞어 모두 나온 뒤 다음 묶음을 섞는다. 특정 조각이 오래 안 나오는 일을 막는다.
- 회전: SRS 표준 회전 상태와 월킥 표(공개된 표 그대로 사용). 월킥 = 벽·블록에 막혀 회전이 안 될 때 한두 칸 옮겨서라도 회전시키는 규칙.
- 등장 위치: 가로 중앙, y=0~1. 등장 위치가 막혀 있으면 게임 오버.

## 6. 게임 진행

### 6.1 상태 흐름

```
시작 → 등장(spawn) → 낙하 → 바닥 닿음 → 잠금 대기(500ms) → 잠금 → 마디 판정
                ↑                                                      │
                └──────────── 지울 줄 없음 ◄────────────────────────────┤
                └──── 지울 줄 있음: 지우기 연출(300ms) + 연주 큐 등록 ◄──┘
게임 오버: 등장 위치가 막힘, 또는 조각 전체가 보이는 영역 위(y<2)에서 잠김
```

- 잠금 대기: 500ms. 이동·회전하면 다시 세되 최대 15회까지만.
- 지우기 연출 300ms 동안 입력은 받되 새 조각은 나오지 않는다. 연주는 연출이 끝나도 계속된다(게임을 막지 않음).
- 줄이 지워지면 위의 줄이 그대로 내려온다(일반 테트리스와 같음).

### 6.2 속도 = 박 단위 낙하

낙하 간격은 "현재 BPM에서 낙하 단위 음표 하나의 길이"다. 조각이 박에 맞춰 떨어진다.

| 레벨 | 낙하 단위 | BPM | 간격(ms) |
|---|---|---|---|
| 1 | 2분음표 | 100 | 1200 |
| 2 | 2분음표 | 120 | 1000 |
| 3 | 4분음표 | 100 | 600 |
| 4 | 4분음표 | 120 | 500 |
| 5 | 4분음표 | 140 | 429 |
| 6 | 8분음표 | 100 | 300 |
| 7 | 8분음표 | 120 | 250 |
| 8 | 8분음표 | 140 | 214 |
| 9 | 16분음표 | 100 | 150 |
| 10 | 16분음표 | 120 | 125 |
| 11+ | 16분음표 | 레벨마다 +10 | 최소 80 |

- 레벨 업: 10마디마다.
- 메트로놈(기본 켬, 작게)이 현재 BPM으로 울린다. 센박은 높은 소리.
- 6칸 보드(3/4·6/8)는 간격 × 1.3.

## 7. 마디 판정 엔진 (핵심)

순수 함수 `analyzeRow(row, meter, rules) → MeasureResult`. 게임 상태·화면과 완전히 분리해 단위 테스트한다.

입력: `row` = 길이 W의 배열, 각 칸은 `null` 또는 `{ pieceId, type }`.

처리 순서:
1. **완성 확인**: `null`이 하나라도 있으면 `{ complete: false }` 반환.
2. **음 나누기(run)**: x=0부터 오른쪽으로 가며 `pieceId`가 같은 연속 구간을 하나의 run으로 묶는다. run = `{ start, length, type, pieceIds }`.
3. **계이름**: `pitch = PITCH_MAP[type]`.
4. **붙임줄(옵션 `rules.ties`)**: 인접 run의 `type`이 같으면 하나로 합치고 `tied: true`. 합친 길이 최대 W.
5. **당김음**: `strength[start] < max(strength[start+1 … start+length-1])`이면 `syncopated: true`. 길이 1이면 항상 false.
   - 뜻: 음이 시작한 자리보다 더 센 박을 덮으며 이어지면 당김음.
6. **화음 마디(`rules.chordBonus`)**: 서로 다른 계이름이 2개 이상이고, 모든 계이름이 {도,미,솔}(Ⅰ)·{파,라,도}(Ⅳ)·{솔,시,레}(Ⅴ) 중 하나에 전부 들어가면 `chord: 'I'|'IV'|'V'`. 두 음의 조합은 세 화음 중 최대 하나에만 속하므로 모호하지 않다(도+솔→Ⅰ, 레+솔→Ⅴ, 도+파→Ⅳ). 계이름이 하나뿐이면 보너스 없음.
7. **패턴**: run 길이 배열(예 `[2,2,2,2]`)을 박자표별 도감(§11, 부록 B)과 비교해 `patternId`. 붙임줄이 켜져 있으면 합친 길이 기준.
8. **표기**: §8 규칙으로 각 run을 `NotationNote[]`로 변환(`lib/notation.ts`).
9. **점수**: §10. 항목별 내역 `breakdown`을 함께 돌려준다.

출력 예:
```json
{
  "complete": true, "y": 15, "meterId": "4/4",
  "notes": [
    { "pitch": "도", "start": 0, "length": 4, "syncopated": false, "tied": false },
    { "pitch": "미", "start": 4, "length": 2, "syncopated": false, "tied": false },
    { "pitch": "솔", "start": 6, "length": 2, "syncopated": false, "tied": false }
  ],
  "syncopationCount": 0, "chord": "I", "patternId": "h-q-q",
  "score": 300, "breakdown": [ { "label": "마디 완성", "points": 100 }, { "label": "Ⅰ 화음 마디", "points": 200 } ]
}
```

여러 줄이 동시에 완성되면 줄마다 따로 판정하고, **위→아래** 순서로 연주 큐에 넣는다(악보 읽는 순서).

## 8. 표기(악보) 규칙

8.1 **길이 → 음표** (한 표기 묶음 안에서): 1=`e`, 2=`q`, 3=`q.`, 4=`h`, 5=`h_e`, 6=`h.`, 7=`h._e`, 8=`w`

8.2 **가상 세로줄 분할**: 음이 표기 묶음 경계(§4.2)를 넘으면 경계에서 잘라 붙임줄로 잇는다. 예외:
- (a) 음이 묶음 경계에서 시작해 묶음 경계에서 끝나면(묶음을 통째로 덮음) 자르지 않는다.
- (b) 마디 전체를 덮으면 자르지 않는다.
- (c) 4/4에서 뒷박(홀수 칸)에서 시작한 4분음표(길이 2)는 중간선을 넘어도 자르지 않는다. 관용 당김음 `e q q q e` 표기.
- (d) 4/4에서 2박에서 시작한 2분음표(칸 2~5)는 자르지 않는다. 관용 표기 `q h q`.
- `rules.strictNotation = true`이면 (c)(d)도 자른다. 기본값은 관용 허용(§19에서 검토).

8.3 **기 묶음(beam)**: 8분음표끼리 같은 기 묶음 안에 있을 때만 잇는다. 4/4는 한 박(2칸), 6/8은 3칸 단위. VexFlow `Beam.generateBeams(notes, { groups })` 사용.

8.4 당김음 음표는 강조색(주황 테두리).

8.5 높은음자리표, 조표 없음(다장조), 옥타브 4. 오선 하나에 마디 하나.

8.6 예시 (4/4, 표기 묶음 [4,4])

| 칸 | 길이 | 표기(기본) | 표기(엄격) |
|---|---|---|---|
| 0~3 | 4 | `h` | `h` |
| 1~3 | 3 | `q.` (뒷박 시작이지만 묶음 안) | `q.` |
| 2~5 | 4 | `h` (예외 d) | `q_q` |
| 3~4 | 2 | `q` (예외 c) | `e_e` |
| 3~6 | 4 | `e_q.` | `e_q.` |
| 2~4 | 3 | `q_e` | `q_e` |
| 6/8 2~3 | 2 | `e_e` | `e_e` |

## 9. 소리

- Tone.js 사용. 첫 터치에서 `Tone.start()` ("소리 켜기" 버튼). iOS는 사용자 터치 전에 소리가 나지 않는다.
- 악기: 스테이지 1은 박수·우드블록(단일음, `MembraneSynth` 또는 짧은 샘플). 스테이지 2부터 멜로디 신스(`Tone.Synth`, triangle). 피아노 샘플(`Tone.Sampler`)은 용량·로딩 때문에 옵션(§19).
- 메트로놈: `Tone.Transport`에 BPM 설정, 박마다 클릭(센박은 높은 소리). 기본 켬, 볼륨 -18dB, 설정에서 끔.
- 마디 연주 큐: 지워진 마디는 **다음 박 경계**에 맞춰 시작한다(메트로놈과 정렬). 각 음은 `start칸 × 8분음표` 시각에 `length칸` 길이로 울린다. 큐에 여러 마디가 있으면 끊김 없이 이어서 연주. 큐 최대 3마디, 넘치면 가장 오래된 것을 버린다(연주 밀림 방지).
- 연주 중 악보 패널의 해당 음표를 하이라이트(재생 헤드).
- 효과음: 이동·회전(아주 짧은 클릭), 잠금(톡), 당김음 보너스(짧은 글리스), 패턴 첫 달성(팡파르 1초).
- 모든 소리는 `Transport` 시각 기준으로 예약한다. 자바스크립트 타이머(`setTimeout`)로 직접 울리지 않는다(지터 방지).

## 14. 학습 피드백

1. **마디 완성 연출(300ms)**: 줄의 칸들이 음 단위로 합쳐져 알약 모양이 되고 그 위에 음표 기호가 뜬 뒤 사라진다. 동시에 악보 패널에 오선보로 나타나 연주되며 재생 헤드가 지나간다. 칸이 음표로 바뀌는 이 순간이 "줄 = 마디"를 이해하는 핵심 장면이다.
2. **점수 항목 텍스트**: §10의 항목 이름을 그대로 띄운다.
3. **고스트 음표 미리보기** (스테이지 1~3 기본 켬, 설정 가능): 조각이 놓일 자리의 각 줄에 생길 음표를 고스트 위에 작게 표시(`q.`, `e`). 리듬을 계획적으로 만들게 한다.
4. **스테이지 시작 카드**: 1~2문장 + 그림 1장 + "시작" 버튼.
5. **패턴 도감**: 첫 달성 토스트 + 도감 화면(악보·이름·달성 횟수).
6. **게임 오버 요약**: 완성 마디 수, 음표 종류별 개수, 당김음 수, 화음 마디 수, 최고 콤보, 새로 등록한 패턴, 이번 판 최고의 마디(점수 기준) 악보.
7. **악보 보기 토글(옵션)**: 쌓인 줄의 빈칸을 쉼표로 보여 준다.

## 16. 기술 스택과 주의사항

- **권장**: Harmony와 같은 스택 — Next.js 15 + TypeScript + Tailwind + shadcn/ui + Zustand(상태) + VexFlow 5(악보) + Tone.js(소리). 테스트는 Vitest. 배포 Vercel. 나중에 Harmony에 모듈로 붙일 수 있다.
- (대안) 게임만 따로 만들면 Vite + React가 더 가볍다. 어느 쪽이든 아래 주의사항은 같다.
- 폴더: `app/`(화면) `components/`(UI) `lib/`(순수 로직: `measure.ts` `notation.ts` `score.ts` `patterns.ts` `srs.ts`) `data/`(박자표·패턴·스테이지 JSON) `store/`(Zustand) `audio/`(Tone.js) `tests/`.

주의사항
1. VexFlow·Tone.js는 브라우저 전용이다. 클라이언트 컴포넌트에서 `dynamic(() => import(...), { ssr: false })`로 불러온다. 서버 렌더링 때 오류 난다.
2. 게임 루프는 `requestAnimationFrame` 한 개에서 낙하 타이머·입력·잠금 대기를 처리한다. `setInterval`을 여러 개 쓰지 않는다. 탭이 뒤로 가면 자동 일시정지(`visibilitychange`).
3. 보드 렌더링은 1차로 CSS Grid(DOM). 최대 12×16칸이라 충분하다. 성능 문제가 생기면 Canvas로 바꾼다(렌더 함수만 교체되도록 분리).
4. 마디 판정·표기·점수·패턴은 순수 함수로 두고 Vitest로 테스트한다. UI와 섞지 않는다.
5. 저장은 localStorage(`SaveData`, `version` 필드 포함). 로그인·순위표는 나중에 Supabase.
6. PWA(홈 화면 추가, 오프라인)는 M7에서.

- 완료 기준: (1) 10분 플레이에 오류 없음 (2) 벽에 붙은 상태에서 회전됨(월킥) (3) 4줄 동시 지우기 가능 (4) 보드 폭을 6·9·12로 바꿔도 동작 (5) 고스트 위치가 정확 (6) 보관(홀드)이 조각당 1회만.

## 20. 용어 정리

- **7-bag**: 조각 7종을 한 묶음으로 섞어 모두 나온 뒤 다시 섞는 무작위 방식.
- **SRS / 월킥**: 표준 회전 규칙 / 막혔을 때 옆으로 밀어서라도 회전시키는 보정.
- **잠금 대기(락 딜레이)**: 조각이 바닥에 닿은 뒤 굳기까지 주는 짧은 시간.
- **고스트**: 조각이 떨어질 자리를 미리 보여 주는 반투명 조각.
- **소프트/하드 드롭**: 빨리 내리기 / 한 번에 바닥까지.
- **DAS/ARR**: 좌우 버튼을 누르고 있을 때 반복 시작까지의 시간 / 반복 간격.
- **퍼펙트 클리어**: 줄을 지워 보드가 완전히 비는 것.
- **BPM**: 1분에 박 몇 번.
- **기(beam)**: 8분음표들을 잇는 가로 막대. **붙임줄(tie)**: 같은 음을 이어 하나로 길게 소리 내는 줄.
- **당김음**: 약한 자리에서 시작해 센 자리를 넘겨 끄는 음. **헤미올라**: 3박 느낌과 2박 느낌이 겹치는 리듬.
- **홑박자/겹박자**: 박이 2개로 나뉘는 박자(3/4) / 3개로 나뉘는 박자(6/8).
- **가상 세로줄**: 4/4 마디 한가운데에 있다고 보는 보이지 않는 선. 음이 이 선을 넘으면 나눠 적는다.
- **주요3화음**: 으뜸(Ⅰ)·버금딸림(Ⅳ)·딸림(Ⅴ) 화음. **동기/작은악절**: 2마디/4마디 단위.
- **PWA**: 홈 화면에 설치해 앱처럼 쓰는 웹. **AudioContext**: 브라우저 소리 엔진(첫 터치 뒤에만 켜짐).
- **Vitest**: 순수 함수를 자동으로 검사하는 테스트 도구.
