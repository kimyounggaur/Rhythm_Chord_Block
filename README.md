# 음악이론 게임 (가칭) v0.1 — 리듬 모드 · 화음 모드

블록을 쌓으며 음악이론을 배우는 **모바일 웹 게임**이에요. 설계서 두 개를 그대로 구현했어요.

| 모드 | 핵심 규칙 | 설계서 |
|---|---|---|
| **리듬 모드** | 한 줄을 빈칸 없이 채우면 **한 마디**가 되어 악보로 그려지고 연주돼요 | `docs/rhythm-tetris-design-v0.1.md` |
| **화음 모드** | 한 화음의 구성음 3개가 모두 든 덩어리가 **4개 이상** 이어지면 터지며 화음이 울려요. 연쇄 = 화음 진행 | `docs/chord-puyo-design-v0.1.md` |

그림은 두 에셋 묶음(`public/assets/rhythm`, `public/assets/chord`)을 그대로 썼어요. 에셋 설명은 `docs/*-assets-README.md`.

## 지금 되는 것 (v0.1)

두 설계서의 개발 단계 **M0~M8 전부 + M10(확장) 일부**를 구현했어요. 자동 테스트 **270개**가 모두 통과해요(리듬 148 · 화음 118 · 공용 4). 테스트에는 설계서 §18의 케이스가 모두 들어 있어요.

| | 리듬 모드 | 화음 모드 |
|---|---|---|
| 규칙 엔진 | 7종 조각·7-bag·SRS 회전과 월킥, 잠금 대기 500ms(최대 15회), 마디 판정 `analyzeRow`(음 나누기·붙임줄·당김음·화음 마디·패턴), 표기 규칙(가상 세로줄 예외 a~d, 엄격 모드), 점수표 §10 | 쌍 낙하·킥·1칸 틈 180° 뒤집기·분리 낙하, 터짐 판정 `findPops`(화음별 BFS·공통음·방해 타일 인접 제거), 해결 루프 `resolve`, 진행·완성·동시 보너스, 점수 공식 §10 |
| 소리(Tone.js) | 메트로놈(센박 높게, −18dB), 완성 마디를 다음 박에 맞춰 연주(최대 3마디 대기), 스테이지 1 우드블록·이후 멜로디, 효과음 | 착지음, 화음 보이싱(근음 옥타브3 + 구성음), 연쇄를 진행으로 들려주기, 해결 효과, 긴장 패드(Ⅰ↔Ⅴ, −24dB) |
| 화면 | VexFlow 악보 패널(기 묶음·붙임줄·점음표·당김음 주황·재생 하이라이트·캡션), 박 번호, 고스트 음표 미리보기, 마디 완성 연출(알약·음표), 악보 보기(쉼표) | 덩어리 받침대(공통음 반반·Ⅴ7 점선), 부족한 음 힌트(최대 3개), 음정 표시, 화음 칩·성부 수, 진행 띠, 역진행 힌트, 긴장 배경 |
| 진행 | 스테이지 1~10(4/4·3/4·6/8·9/8·12/8·5/4·7/8), 무한 모드, 패턴 도감, 게임 오버 요약 | 스테이지 1~10(Ⅴ7·가단조 솔♯ 포함), 무한 모드, 연쇄 퍼즐 5개, 진행 도감, 게임 오버 요약 |
| 조작 | 버튼(누르고 있으면 반복)·제스처·키보드, 보관(홀드) | 버튼·제스처·키보드(보관 없음, 설계서 §16-7) |
| 저장 | 최고 점수·클리어·도감·설정이 새로고침 뒤에도 남음(localStorage) | 같음 |

공통: 한 앱 두 라우트(`/rhythm`, `/chord`), 360×780 세로 화면 기준 배치(390×844, 412×915도 확인), 가로로 눕히면 "세로로 돌려 주세요", 탭이 가려지면 자동 일시정지, PWA(홈 화면 추가 뒤 오프라인 실행 확인).

### 설계서를 해석해서 정한 곳 (확인해 주세요)

- **리듬 §18 케이스 5 점수 예시(300점)** 는 패턴 첫 달성 +500을 빼고 계산돼 있어요. §10·§11 규칙대로 구현했어요(도감이 열린 스테이지에서는 800점, 다시 만들면 400점).
- **리듬 스테이지 1은 패턴 도감이 닫혀 있어요**(§12 표에서 '도감 열림'이 스테이지 2부터).
- **리듬 스테이지 10** 은 5/4로 15마디 → 카드와 함께 보드를 비우고 7/8로 15마디.
- **리듬 짧은 효과음**(이동·회전·잠금)은 반응 지연을 줄이려고 오디오 시계로 바로 울려요. 음악·메트로놈·마디 연주는 설계서대로 Transport 기준이에요.
- **화음 §18 T6 격자와 부록 C 퍼즐 예시** 는 §7 규칙대로 하면 첫 단계에 Ⅰ과 Ⅴ가 함께 터져요(설계서 안의 작은 모순). 의도한 2연쇄(Ⅴ→Ⅰ, 600점)가 나오도록 격자를 고쳐 테스트했고, 원래 격자의 실제 결과(800점, 공통음 솔)도 따로 테스트해 두었어요.
- **화음 여러 목표 스테이지**: 2(Ⅴ 10번 + 전체 20번), 3(Ⅰ·Ⅳ·Ⅴ 각 5번), 5(변격 3번 + 반마침 3번). 설계서에 비어 있던 **스테이지 10 목표는 ⅰ·ⅳ·Ⅴ 각 5번**으로 정했어요.
- **화음 방해 타일** 은 스테이지 8~10에서 나와요(§6.3 "스테이지 8부터").
- **확장 화음의 진행 보너스** 는 화성 기능대로 Ⅳ→Ⅴ7 +4, 단조 Ⅴ→ⅰ +8을 줬어요.
- **연쇄 퍼즐** 은 저절로 떨어지지 않고 직접 놓아요. 화음 설정에 '모든 스테이지 열기'(선생님용)를 더했어요.

### 아직 안 한 것 / 사람이 해야 할 것

- **M9 플레이테스트**(학생 3~5명, 1주): 관찰·조정 항목은 각 설계서 §17 M9에 있어요.
- **실제 휴대폰 확인**: 아이폰 사파리·안드로이드 크롬에서 첫 터치 뒤 소리, 두 손가락 탭·플릭 제스처. (크로미움 자동 점검으로만 확인했어요)
- **나중 단계**: Supabase 순위표, 대전 모드(규격만 준비: 리듬 `MeasureResult`, 화음 `ChordBattleAdapter` = 점수 ÷ 60), 리듬의 피아노 샘플·스테이지 사이 퀴즈·조표, 화음의 3타일 화음 조각·음정 장/단 표시.
- **설계서 §19 결정 필요 항목**: 게임 이름(지금은 가칭 '음악이론 게임'), 표기 예외 범위(음악 교사 검토), 힌트·긴장 패드 기본값 등.

## 내 컴퓨터에서 실행하기

필요한 것: Node.js 20 이상.

```bash
npm install
npm run dev        # http://localhost:3000  → /rhythm, /chord
npm test           # 자동 테스트(설계서 §18 케이스 포함)
npm run build      # 배포용 정적 사이트 out/ + 오프라인용 서비스 워커
```

- 휴대폰으로 보려면 같은 와이파이에서 `npm run dev -- -H 0.0.0.0` 로 띄우고 휴대폰 브라우저에서 `http://<컴퓨터 IP>:3000` 을 여세요.
- 키보드: ← → 이동, ↑/X 시계 회전, Z 반시계, ↓ 천천히 내리기, Space 한 번에 내리기, C 보관(리듬 모드), P 일시정지.

## 인터넷에 올리기 (Vercel, 설계서 §16)

1. 이 폴더를 GitHub 저장소로 올립니다(GitHub Desktop → **File → Add Local Repository** → **Publish repository**).
2. [vercel.com](https://vercel.com) → **Add New… → Project** → 방금 올린 저장소 **Import** → 설정은 그대로 두고 **Deploy**.
3. 끝나면 `https://<프로젝트이름>.vercel.app` 주소가 생겨요. 휴대폰에서 열고 **공유 → 홈 화면에 추가**하면 앱처럼 쓰고, 한 번 연 뒤에는 인터넷 없이도 돼요(PWA).

서버가 필요 없는 정적 사이트라 Vercel 말고도 아무 정적 호스팅(Netlify, GitHub Pages, S3 등)에 `out/` 폴더만 올려도 돼요.

## 바로 해 보기용 한 장짜리 배포본

`npm run build:play` 는 같은 화면 코드를 상대 경로로 묶어 `artifact/dist/` 에 만들어요(주소 `#rhythm`, `#chord`). claude.ai 아티팩트처럼 하위 주소에 올라가는 곳에서 미리 해 볼 때 썼어요. 이 배포본은 서비스 워커(오프라인)를 쓰지 않아요.

## 폴더 구조

`CLAUDE.md` 에 자세히 있어요. 요약하면:

- `lib/rhythm`, `lib/chord` — 게임 규칙(순수 함수, 화면과 분리) · `tests/` 에서 자동 검사

- `data/rhythm`, `data/chord` — 설계서 부록의 JSON(박자표·패턴·스테이지 / 화음·진행·스테이지·퍼즐)
